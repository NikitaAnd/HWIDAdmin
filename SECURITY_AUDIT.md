## ✅ Что сделано правильно

### 1. Безопасный сбор HWID (HwidCollector.java)
- **Нет внешних библиотек** (OSHI/JNA) — минимальная поверхность атаки
- Все команды `ProcessBuilder` используют **жёстко закодированные массивы строк**, а не конкатенацию — **инъекция команд невозможна**
- Таймаут 5 секунд на каждый процесс — защита от зависаний
- Корректная обработка ошибок (все исключения ловятся, возвращают `null`)
- `Process.destroyForcibly()` + `Process.destroy()` в `finally` — нет утечек процессов

### 2. Криптография
- **SHA-256** для хеширования HWID — криптографически стойкий алгоритм
- Соль-префикс `"hwidadmin|" + PROVIDER + "|"` — защита от rainbow-table атак
- Хешируется на клиенте, сервер видит только хеш — raw HWID не покидает машину

### 3. Валидация сетевого протокола (HwidMessageListener.java)
- Строгая проверка magic byte (`0xA1`)
- Проверка тега (`"mod"`, 3 байта)
- Ограничение длины payload: `1 ≤ len ≤ 512`
- Проверка `len > buf.remaining()` — защита от buffer overread
- Минимальная длина нормализованного HWID: 16 символов
- Все ошибки парсинга обрабатываются как `IllegalArgumentException` с логированием

### 4. Контроль доступа
- Команды `/hwidadmin reload` и `/hwidadmin status` защищены permissions (`hwidadmin.reload`, `hwidadmin.status`)
- Права по умолчанию — только для OP
- Проверка `isProtected()` — HWID-проверка применяется только к OP/привилегированным игрокам

### 5. Изоляция мода
- `clientSideOnly=true` — мод **никогда** не загружается на сервере
- Канал `optional()` / `acceptMissingOr` — мод не ломает подключение к серверам без плагина
- Access transformers пусты (`accessTransformers = []`) — мод не модифицирует внутренние классы Minecraft

### 6. Отсутствие опасных паттернов
- ❌ Нет reflection (`Class.forName`, `setAccessible`)
- ❌ Нет десериализации (`ObjectInputStream`, `readObject`)
- ❌ Нет HTTP/URL соединений (мод никуда не стучится)
- ❌ Нет записи файлов
- ❌ Нет ScriptEngine / eval
- ❌ Нет хардкод-IP адресов
- ❌ Нет Base64-encoded строк или обфусцированного кода

### 7. CI/CD безопасность
- GitHub Actions использует только `secrets.GITHUB_TOKEN` (автогенерируемый)
- Нет хардкод-credentials в workflow
- `.gitignore` исключает `*.yml.bak` (защита от случайного коммита конфига с реальными HWID)

### 8. Консистентность кода
- `HwidCollector.java` **идентичен** во всех 6 версиях
- `HwidMessageListener.java` **идентичен** во всех 6 версиях плагина
- Различия между версиями — только в API-обёртках Forge (NetworkRegistry vs ChannelBuilder)

## ⚠️ Обнаруженные проблемы дизайна

### ПРОБЛЕМА #1: Отсутствие таймаута проверки HWID (Высокая)

**Суть:** Плагин проверяет HWID **только когда получит пакет от мода**. Если мод не установлен, сломан или пакет потерян — сервер **никогда не узнает** об этом, и «защищённый» игрок (OP/с правами) останется на сервере **без какой-либо проверки**.

**Сценарий атаки:**
1. Админ раздаёт OP-права и ожидает, что HWIDAdmin защитит от «утёкших» аккаунтов
2. Злоумышленник получает доступ к OP-аккаунту
3. Злоумышленник заходит **без мода** (или с отключённым модом)
4. Плагин **не получает HWID-пакет** → **не выполняет проверку** → **не кикает**
5. Злоумышленник имеет полный OP-доступ

**Рекомендация:** Добавить таймер в `HwidAdminPlugin` / `HwidMessageListener`:
```java
// При PlayerJoinEvent: если игрок "защищённый", запускаем таймер на N секунд.
// Если за N секунд HWID-пакет не получен — кикаем с сообщением
// "Установите мод HWIDAdmin для подтверждения доступа".
```

---

### ПРОБЛЕМА #2: Доверие клиентскому HWID (Средняя)

**Суть:** Клиентский мод вычисляет HWID и отправляет его серверу. **Модифицированный клиент** (Forge core mod, mixin, прокси) может отправить **произвольный HWID** в пакете, включая тот, что находится в whitelist.

**Сценарий атаки:**
1. Злоумышленник знает HWID авторизованного админа (например, из логов сервера)
2. Злоумышленник пишет простой мод/прокси, который отправляет пакет `hwidadmin:main` с чужим HWID
3. Плагин принимает поддельный HWID и пропускает злоумышленника

**Митигация (уже частично реализована):**
- HWID не виден в моде (мод одинаковый у всех) ✅
- Канал `hwidadmin:main` нестандартный — обычный клиент его не отправит ✅
- Но: формат протокола прост и описан в комментариях кода ❌

**Рекомендация:** Это **фундаментальное ограничение** клиент-серверной модели Minecraft. Для усиления можно:
1. Добавить challenge-response: сервер отправляет случайный nonce, клиент подписывает его вместе с HWID
2. Добавить привязку к UUID Minecraft-аккаунта (чтобы HWID + UUID работали только вместе)
3. **Не логировать HWID в открытом виде** (см. замечание #3)

## ℹ️ Низкоуровневые замечания

### Замечание #1: Слабый fallback HWID

**Файл:** `HwidCollector.java`, строка 45  
```java
v = "unknown-" + System.getProperty("user.name", "user");
```

Если все источники HWID недоступны, хеш строится от `user.name`. Проблемы:
- `user.name` легко подменить через `-Duser.name=xxx`
- У многих пользователей `user.name` одинаковый (`"user"`, `"admin"`, `"minecraft"`)
- Все такие пользователи получат **одинаковый** HWID-хеш

**Риск:** Низкий (фоллбэк срабатывает крайне редко).

---

### Замечание #2: SHA-256 fallback на hashCode()

**Файл:** `HwidCollector.java`, строка 121  
```java
} catch (Exception e) {
    return String.valueOf(input.hashCode());
}
```

Если `MessageDigest.getInstance("SHA-256")` выбросит исключение (крайне маловероятно — SHA-256 есть во всех JVM), используется 32-битный `hashCode()` — криптографически нестойкий.

**Риск:** Минимальный (SHA-256 гарантирован спецификацией Java).

---

### Замечание #3: Логирование HWID в открытом виде

**Файлы:** `HwidMessageListener.java`, `HwidSender.java`  
```java
// Серверный лог:
plugin.getLogger().info("HWID OK " + player.getName() + " (hwid=" + hwid + ")");
plugin.getLogger().warning("Unwhitelisted HWID from " + player.getName() + " — HWID: " + hwid);

// Клиентский лог:
HwidadminMod.log().info("HWIDAdmin: provider={}, raw={}, hash={}", ...);
```

Любой с доступом к логам сервера или клиента может узнать HWID. В сочетании с проблемой #2 это позволяет подделать авторизацию.

**Рекомендация:** В логах показывать только первые/последние 8 символов хеша:
```java
plugin.getLogger().info("HWID OK " + player.getName() + " (hwid=" + hwid.substring(0, 8) + "...)");
```

---

### Замечание #4: Нет защиты от replay-атак

Протокол не включает nonce, timestamp или sequence number. Перехваченный пакет с HWID может быть воспроизведён без изменений.

**Риск:** Низкий (в сочетании с проблемой #2, но сам по себе не создаёт новой угрозы — пакет всё равно привязан к конкретному подключению игрока).

## 🏁 Заключение

**HWIDAdmin не содержит уязвимостей, дыр безопасности или нулевых дней** в классическом понимании (RCE, инъекции, обход авторизации через баги кода).

Код написан аккуратно, с правильной валидацией входных данных, без опасных паттернов и без сторонних зависимостей.

**Две основные проблемы** носят архитектурный характер и присущи любой системе клиентской HWID-аутентификации в Minecraft:

1. **Отсутствие таймаута** — защищённый игрок без мода не проверяется вообще *(рекомендую исправить в первую очередь)*
2. **Доверие клиентскому пакету** — модифицированный клиент может подделать HWID *(фундаментальное ограничение, частично митигируется закрытием HWID в логах)*

Обе проблемы **не являются уязвимостями в коде**, а представляют собой проектные решения, которые можно усилить.
