# HWIDAdmin

Пара «мод + плагин» для Minecraft **1.20.1**, которая даёт попасть на сервер
(и остаться на нём) только игрокам, чей **HWID** компьютера есть в белом списке
на сервере.

## Как это работает

1. **Клиентский мод (Forge)** при заходе на сервер вычисляет HWID машины и
   отправляет его плагину. **В самом моде НИГДЕ не хранится «правильный» HWID** —
   мод у всех одинаковый.
2. **Серверный плагин (Spigot/Paper)** держит список разрешённых HWID в
   `plugins/HWIDAdmin/config.yml`. Если мод прислал HWID, которого нет в списке, —
   игрока **кикает**. Права при этом плагин не трогает: они у админа уже есть.

> Смысл: чужой или «утёкший» .jar бесполезен. Кто угодно может его поставить,
> но HWID компьютера не совпадёт → кик. HWID администратора никто посторонний
> не знает, потому что он хранится только в конфиге на сервере.

## Состав репозитория

```
mod/     — Forge-мод для клиента (Minecraft 1.20.1, Forge 47.x, Java 17)
plugin/  — Bukkit/Spigot/Paper плагин (spigot-api 1.20.1-R0.1-SNAPSHOT)
```

## Сборка

Готовые jar-файлы собираются автоматически при каждом пуше (GitHub Actions)
и публикуются в **GitHub Releases**. Свежую сборку всегда можно скачать здесь:

- **Мод (Forge 1.20.1):** `HWIDAdmin-mod-1.0.0.jar`
- **Плагин (Spigot/Paper 1.20.1):** `HWIDAdmin-plugin-1.0.0.jar`

Ссылка на последний выпуск:
`https://github.com/NikitaAnd/HWIDAdmin/releases/latest`
(или вкладка **Releases** репозитория → выбрать сборку **build-N**).

Собрать вручную:

Требования: JDK 17, Gradle 8.8 (для мода, через встроенный `gradlew`), Maven 3.9+ (для плагина).

```bash
# мод
cd mod
./gradlew build            # результат: mod/build/libs/hwidadmin-1.0.0.jar

# плагин
cd ../plugin
mvn -B package             # результат: plugin/target/HWIDAdmin-1.0.0.jar
```

## Установка

**Плагин:**
1. Положи `HWIDAdmin-<version>.jar` в `plugins/` сервера (Spigot/Paper 1.20.1).
2. Перезапусти сервер — появится `plugins/HWIDAdmin/config.yml`.

**Мод:**
1. Установи **Forge 47.x для 1.20.1** (если ещё не стоит).
2. Положи `hwidadmin-1.0.0.jar` в папку `mods` клиента.

## Первая настройка (главное)

1. Дай мод тем, кому можно заходить с правами админа.
2. Узнай их HWID **одним из двух способов**:
   - зайди с нужной машины на сервер и набери в чате команду **`/hwid`**
     (мод покажет HWID прямо в чате; также при входе он пишет
     «Твой HWID: …», если `showHwidOnJoin: true` в клиентском конфиге);
   - либо посмотри консоль сервера: при кике пишется
     `[HWIDAdmin] Unwhitelisted HWID from <ник> — HWID: <hash>`.
3. Впиши полученный хеш в `config.yml` в секцию `allowed-hwids`:
   ```yaml
   allowed-hwids:
     - "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
   ```
4. Выполни **`/hwidadmin reload`** (или перезапусти сервер).

Обрати внимание: в `config.yml` из коробки лежит заведомо «пустой» хеш-заглушка
`0000…0000` — удали её и впиши настоящие.

## Команды и поведение

| Команда | Право | Что делает |
| --- | --- | --- |
| `/hwidadmin reload` | `hwidadmin.reload` | перечитывает `config.yml` |
| `/hwidadmin status` | `hwidadmin.status` | показывает канал, размер whitelist, режим кика |

Настройки плагина (`config.yml`):

```yaml
channel: "hwidadmin:main"   # должен совпадать с каналом в моде (не меняй без нужды)
allowed-hwids: []           # список разрешённых SHA-256 HWID
kick-unlisted: true         # кикать ли при несовпадении (false = только логировать)
kick-message: "&cДоступ запрещён: твой HWID не в белом списке."

check-op: true              # проверять ли серверных OP
required-permissions: []    # права, которые тоже делают игрока «проверяемым»
                            # (пример: ["some.group.admin", "server.admin"])
```

### Кого плагин проверяет

Проверка HWID (и кик) выполняется **только для «защищённых» игроков** — тех,
кто является OP сервера и/или имеет любое право из списка `required-permissions`
(проверяется через стандартную систему прав, так что LuckPerms и любые
permission-плагины работают автоматически). Обычные игроки, у которых стоит мод,
полностью игнорируются.

Таким образом можно не раздавать OP, а назначить группу/право (например, через
LuckPerms) и вписать это право в `required-permissions` — тогда, к примеру, свои
хелперы или модераторы с админ-правами тоже будут проверяться по HWID.

Настройки мода (`config/hwidadmin-client.toml` у клиента):

- `showHwidOnJoin` — показывать свой HWID в чате при входе (по умолчанию `true`,
  удобно при первичной настройке; после — можно выключить);
- `pingInterval` — как часто (в секундах) мод повторно шлёт HWID, чтобы проверка
  оставалась актуальной при переподключениях/потере пакета.

## Как считается HWID

Клиентский мод берёт стабильный идентификатор машины (без внешних библиотек):

| ОС | Источник |
| --- | --- |
| Windows | `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid` |
| macOS | `ioreg -rd1 -c IOPlatformExpertDevice` (IOPlatformUUID) |
| Linux | `/etc/machine-id` → `/var/lib/dbus/machine-id` → `/sys/class/dmi/id/product_uuid` |

От этого значения берётся SHA-256 с префиксом → строка из 64 hex-символов,
её и сравнивает плагин.

## Важные технические детали

- Мод регистрирует Forge-канал как **optional / acceptMissingOr** — значит Forge
  клиент с модом **спокойно заходит на ванильный пустой Bukkit-сервер** (сервер
  вообще не участвует в Forge-хендшейке).
- Канал: `hwidadmin:main` (plugin-messaging). Плагин слушает его через
  `registerIncomingPluginChannel`.
- Мод — строго клиентский (`clientSideOnly = true`), на серверной стороне не грузится.
